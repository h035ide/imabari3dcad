# EVOSHIP ヘルプ RAG 実装計画・仕様書

## 1. 背景と目的
- `EVOSHIP_HELP_FILES` 配下の HTML ヘルプ資産をドキュメント質問応答ワークロードに活用する。
- 外部モジュール依存を極力排し、実行ロジックを単一 Python ファイル（候補: `helpfile_parser.py`）に集約する。
- Chroma・Neo4j・LangChain・LlamaIndex を活用したハイブリッド RAG を段階的に整備し、随時リファクタリングを行う。
- 各フェーズで得られた設計・改善結果を可能な限りドキュメント化し、将来の運用に備える。

## 2. 要件と制約
- **段階的アプローチ**: フェーズ単位で実装 → 検証 → リファクタリング → ドキュメント更新を繰り返す。
- **シングルファイル実装**: データ処理・ロード・RAG 推論・評価までのロジックを `helpfile_parser.py` 内に配置し、外部スクリプト依存を避ける。共通関数は同ファイル内でモジュール化。
- **主要ライブラリ**: Chroma (ベクトルストア)、Neo4j (関係グラフ)、LangChain / LlamaIndex (RAG フレームワーク) を積極的に利用し、それぞれに切替可能なインターフェースを整備する。
- **簡潔なリファクタリング**: コードは常に可読性・単純さを最優先し、フェーズ終了ごとに不要コード・冗長ロジックを削減。
- **ドキュメント更新**: 重要な設計判断・設定値・評価結果は本ファイルまたは `doc/` 配下の関連資料へ追記。更新日時を明記。
- **既存実装との整合**: `graphrag_gpt/` 等の既存 RAG 基盤と重複しないよう機能調査を行い、再利用可能な処理は取り込み/統合する。

## 3. 段階的実装フロー

### フェーズ 1: HTML 調査と抽出基盤
- `EVOSHIP_HELP_FILES` の HTML 構造を解析し、本文取得に不要なタグ（`script`, `style`, `media/` 参照など）を除外する BeautifulSoup ベースのクレンジング処理を実装。
- ファイル名、ディレクトリ階層、見出し（`<h1>`〜`<h4>`）をメタデータとして抽出。
- 抽出処理の単体テスト関数を同ファイルに追加し、主要なパターン（コマンド解説、UDF 例など）をカバー。
- フェーズ完了時にコード整理とドキュメント追記。
- **進捗 (2025-10-30)**: `helpfile_parser.py` に抽出ロジック・メタデータ生成・内蔵スモークテストを実装し、CLI から `extract`/`self-test` を利用可能にした。

### フェーズ 2: チャンク化とベクトル化
- 見出しや段落構造に基づくチャンク化ルールを定義（見出し分割 + トークン制限 + オーバーラップ制御）。
- LangChain の `RecursiveCharacterTextSplitter` や LlamaIndex の `NodeParser` を併用し、チャンク粒度を比較。
- Chroma によるベクトルインデックスを作成し、保存/更新 API を同ファイルに実装。
- Neo4j へメタデータグラフ（ドキュメント→セクション→トピック）を同期する処理を構築。
- 進捗をドキュメント化し、冗長コードをリファクタリング。

### フェーズ 3: RAG 検索・応答パイプライン
- LangChain Retriever と LlamaIndex QueryEngine を切替可能な形で実装。
- ベクトル検索 + メタデータフィルタ + Neo4j 経路探索を組み合わせたハイブリッド検索を提供。
- 応答生成に使用する LLM（ローカルまたは API）を抽象化し、証拠文と信頼スコアを添付。
- arXiv:2411.02959v1 の知見（構造化コンテキスト供給、文脈整形など）を適用。具体的には
  - テキスト構造を保ったままコンテキストを LLM に渡す
  - 重要文脈を先頭に再配置するプリプロンプターを挿入
- 定期的にコード整理とコメント整備を実施。

### フェーズ 4: 評価・運用計画
- テスト質問セット（既知の操作手順・コマンド説明など）を用意し、再現性のある RAG 評価スクリプトを実装。
- Precision@k、Recall@k、LLM 評価（自動判定プロンプト）で品質を定量化。
- 更新パイプライン（新規/変更 HTML を検出→再インデックス→QA）を策定し、段階的な CI/CD 連携を検討。
- 定期レビュー用にドキュメントへ評価結果・改善点を追記。

## 4. 詳細仕様

| 項目 | 仕様 |
| --- | --- |
| 入力データ | `EVOSHIP_HELP_FILES` 直下の HTML ファイル群。`media/` 等の非本文ディレクトリは除外。 |
| 抽出方法 | BeautifulSoup による DOM 解析。`<script>`/`<style>`/ナビゲーション要素は削除。改行・空白は正規化。 |
| メタデータ | `source_path`, `title`, `section_hierarchy`, `last_modified`, `keywords`（見出し語 + 固有語抽出）を付与。 |
| チャンク化 | 目安 350–500 トークン。見出し単位 + オーバーラップ 50 トークン。LangChain Splitter/ LlamaIndex NodeParser をサポート。 |
| ベクトル埋め込み | LangChain `HuggingFaceEmbeddings` などローカルモデル優先。Chroma に格納。 |
| グラフ同期 | Neo4j にドキュメント→セクション→用語ノードとリレーションを作成。重複はマージキーで防止。 |
| Retriever | LangChain `MultiVectorRetriever` + Neo4j クエリブースト。LlamaIndex では `QueryEngine` を併用。 |
| 応答生成 | LangChain `ConversationalRetrievalChain` または LlamaIndex `ResponseSynthesizer`。引用元スニペットを添付し、信頼スコアを計算。 |
| 評価 | 自動 QA (ゴールドアンサ比較)、人手レビュー、自己回帰プロンプトによる信頼度分析。 |
| ロギング | フェーズ毎の進捗・エラー・リファクタ履歴を `doc/` 配下ドキュメントに記録。 |
