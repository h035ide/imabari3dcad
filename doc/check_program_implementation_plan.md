# 抽出チェックプログラム実装計画

## 目的
- `data/src/api.txt` から「お手本データ（テンプレート）」を初回生成し、ユーザーが手動で校正・編集できるようにする。
- 校正済みテンプレートに基づき、`doc_preprocessor_hybrid/out/structured_api.json` などの出力を検証する仕組みを整える。
- 返り値・パラメータなど主要情報のみを比較対象とし、目視確認に適したレポートを出力する。

## 要求整理
- 入力：元ドキュメント（`api.txt`、将来的に `api_arg.txt` も考慮）と既存構造化 JSON（`structured_api.json`）。
- 出力：
  - 主レポート（Markdown／端末出力）にメソッド単位の `expected_only` / `parsed_only` / `mismatched` 一覧。
  - オプションで XML/YAML 形式のサマリーファイルを出力し、Excel 等での再加工を容易にする。
- 使用言語：Python（既存ツールチェーンに合わせる）。
- 実行場所：`doc_preprocessor_hybrid` 配下（既存ユーティリティ類に近接）。

## 実装方針
1. **テンプレート生成フェーズ**：
   - `〇タイトル` → 返り値行 → メソッドシグネチャの順で走査し、返り値とパラメータ情報を抽出。
   - 抽出結果を XML テンプレート（`api_template.xml`）として保存。初回生成のみ自動化し、その後はユーザーが手動編集可能とする。
2. **検証フェーズ**：
   - 校正済みテンプレート（XML）を読み込み、`structured_api.json` の内容と照合。
   - メソッド存在有無、返り値テキスト、パラメータ名リスト（および件数）を比較対象とする。
   - レポートは Markdown を基本とし、オプションで XML/YAML 形式の差分レポートも出力できるようにする。
3. **CLI 設計**：
   - `generate-template` コマンドでテンプレート生成。
   - `validate` コマンド（もしくは専用スクリプト）でテンプレートと実データの比較検証。
4. **テスト戦略**：
   - `CreateVariable` のような特殊書式もテンプレートに含まれることを確認する最小テストケースを用意。
   - テンプレートを編集したケースを模した検証テストも検討。

- レポート内で diff ハイライトを簡略表示（例：パラメータ不足/余剰数だけを記載）すると目視確認がさらに楽になる。
