# LlamaIndex形式データ作成 実装計画

## ゴール
- 既存のNeo4jデータをLlamaIndexが期待する`__Node__`/`__Entity__`構造で生成または変換できるようにする。
- `main_0905.py`からLlamaIndex形式パイプラインを実行可能にし、`engine.query()`が実データで結果を返せる状態を構築する。
- 既存の処理（従来ラベルのグラフ生成・ベクトル化）との互換性を維持する。

## 前提確認
- [ ] Neo4jにAPOCがインストールされているか確認する。
- [ ] `.env`に`NEO4J_URI`等の接続情報が設定されているか確認する。
- [ ] OpenAI APIキー（埋め込み/LLM）が利用可能か確認する。
- [ ] 既存データのバックアップを取得する（必要に応じてエクスポート）。

## フェーズ1: 設計・方針決定
- [✅] LlamaIndex形式ノード/リレーションの正確なスキーマを整理する（`__Node__`, `__Entity__`, `Chunk`等）。
- [✅] 既存スキーマとのマッピング方針を決定する（Function/Parameter → __Entity__、説明チャンク → __Node__）。
- [✅] 変換タイミングを決定する（インポート時に生成するか、既存データを後処理するか）。
- [✅] 設定フラグ/CLIオプションのインターフェースを決定する（例: `--llamaindex-format`）。

## フェーズ2: `neo4j_importer.py` 修正
- [✅] `Neo4jImporter`にLlamaIndex形式生成を制御するフラグを追加する。
- [✅] Functionノード読込時に対応する`__Entity__`ノードを`MERGE`する処理を実装する。
- [✅] Parameter/ObjectDefinition/Typeに対する`__Entity__`変換ロジックを追加する。
- [✅] Function説明・引数情報から`__Node__`(Chunk)を生成し`HAS_CHUNK`リレーションを張る処理を追加する。
- [✅] `__Entity__`間・`__Node__`間の必要なリレーション（例: `HAS_PARAMETER_ENTITY`, `MENTIONS`等）を設計し、生成する。
- [✅] 変換処理が既存の`MERGE`/`SET`と競合しないよう重複回避を実装する。
- [✅] 既存スキーマとの整合性チェック（`MAPS_TO`等の関連付け）を行う。
- [✅] インポート完了後に制約・インデックスを作成するクエリ（`__Node__`, `__Entity__`, vector index）を追加する。

## フェーズ3: `main_helper_0905.py` 拡張
- [✅] LlamaIndex形式の存在確認ファンクションを追加する（`MATCH (n:__Entity__)`）。
- [✅] 存在しない場合に変換処理を呼び出す`convert_to_llamaindex_format`ユーティリティを実装する。
- [✅] `build_graph_engine`で変換処理を組み込み、`PropertyGraphIndex.from_existing`が成功する状態を保証する。
- [✅] ログ出力を追加し、変換やクエリ処理の進行を可視化する。
- [✅] 変換関数が冪等であること（再実行で重複が生じない）を確認する。

## フェーズ4: `main_0905.py` 更新
- [✅] LlamaIndex形式パイプライン用の新しいコマンド（例: `llamaindex_pipeline`）を追加する。
- [✅] 既存パイプラインからの呼び出し順序（インポート → 変換 → ベクトル化 → QA）を整理する。
- [✅] CLIヘルプと説明文を更新し、利用方法を明記する。
- [✅] ログメッセージ/ユーザーフィードバックを追加し、進行状況を表示する。

## フェーズ5: 検証
- [✅] 新規インポート後にNeo4j内で`__Node__`/`__Entity__`が生成されているか確認する。
- [✅] `uv run python main_0905.py -f llamaindex_pipeline`を実行し、エラーが無いか確認する。
- [✅] `uv run python main_0905.py -f qa -q "CreateVariableの引数と返り値"`で結果が返るか検証する。
